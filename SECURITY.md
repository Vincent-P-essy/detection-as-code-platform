# Security policy

## Supported version

The current `main` line is supported. This is a portfolio demonstrator, not a
hosted service or production security product.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could put users at risk.
Contact the repository owner through the private contact method on their GitHub
profile and include the affected version, reproduction steps, impact, and any
proposed mitigation. Avoid including real secrets, production telemetry, or active
malware.

You should receive an acknowledgement within seven days. Disclosure timing will be
coordinated after validation and a fix are available.

## Safe research scope

Use only inert fixtures and systems you own or are authorized to test. The project
does not need network scanning, persistence, credential access, or execution of
offensive payloads to reproduce any test.
